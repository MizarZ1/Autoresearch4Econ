# 阶段 3 验收记录

日期：2026-10-10。范围为开发计划「自有研究循环」。模型生成动作和 Stata 主体
代码，程序管理分发、预算、错误、人工等待及结果来源；并发审阅、完整研究 CLI、
真实人工修改和论文导出仍属阶段 4–6。当前交付不是 M1 整体完成。

## 实现及约定

- 工具说明和动作 JSON schema 使用同一契约；严格校验实例字段，再按本机方法
  能力和确认设计分发。通用命令使用同一后端，未规范化输出保留原始证据。
- 上下文包含数据摘要、材料快照引用、方法能力、当前确认设计、有效结果、预算
  和近期真实反馈。补充分析的依据必须是本轮模型请求实际收到的当前结果。
- 每次真实 API 请求单独登记，保存脱敏请求、响应、返回模型、UTC 时间及耗时。
  SDK 重试为 0，最多一次显式传输重试；同操作各请求保留不同 ID 和重试号。
  修正动作后再次决策属于新操作。HTTP 成功与动作解析成功独立记录。
- 保存供应商原始 usage；映射输入、输出、总量、缓存和推理用量，缺失保持 null，
  不把缓存/推理子项再次加入总量。异常正文和实际凭证不进入调用记录。
- 新分析增加研究轮次；修复失败分析保持规格及 operation，只增加 attempt 和
  tool call，默认最多修复两次。只能引用最近一次且已确认停止的失败尝试。
  连续两次错误暂停，调用数及累计活动时间还有独立预算。
- 模型提出设计或实质问题时持久化人工请求并返回 WAITING_HUMAN；不能自行确认。
  检查点保存近期反馈、查询缓存和耗时，重新进入 API 不重复初始化；有未终结
  调用时先核对恢复状态。完整 CLI 恢复仍待阶段 5。
- 结束动作接受当前有效结果及其关联输入、代码、原始返回和核验证据，拒绝无关
  或过期文件。保存结论草稿后为 PAUSED，不能伪造完整论文或整项研究 COMPLETED。

AnalysisArguments 新增可选的 `iv` 和 `retry_attempt_id`，旧动作仍可按默认值读取。
IVSpecification 移到共用 schemas 并在原 stata_contracts 位置兼容导出，持久化内容
不变。小接口增加可选的请求上下文、剩余时间和模型来源参数。九表 SQLite v1、
应用版本 0.1.0 及依赖锁文件均保持原版本，无数据库迁移及新增依赖。

把两规格区间重叠当作正式的系数差异检验。

## 联调发现与失败留痕

通过前的三次运行均保留，没有改写为成功：

1. 模型在动作顶层添加 schema 的 type 字段，两次 HTTP 成功但解析失败，未启动
   统计分析。补充明确实例提示、具体字段错误及额外字段回归测试，保留严格契约。
2. 模型把确认方法 ivregress 2sls 缩写为 ivregress，并把筛选变量加入估计变量。
   两次参数校验失败，无 attempt。工具说明及反馈明确设计方法和 IV 变量顺序。
3. 两项真实 IV 已成功，但结束动作引用原始返回及核验文件，被过窄的结果 ID
   校验拒绝。改为验证当前结果的确切证据关联，增加合法原始证据及无关产物测试。

先前失败运行及调用摘要列在脱敏证据中，原始 trace 留在各自 run；本次成功运行
的计数不抹去联调请求。三个旧 run 总计 8 次实际模型请求，成功 run 为 3 次。
