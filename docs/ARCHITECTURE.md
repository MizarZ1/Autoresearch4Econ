# 阶段 1–7 架构与状态约定

`cli.py` 负责中文配置检查和退出码。`config.py` 保存端点、模型与密钥变量名，
密钥只在请求时读取，不进入产物。`stata_transport.py` 在 POSIX 上隔离原生输出
和协议 stdout，启动固定版本原样服务。生产执行器和自有研究循环已接入。

## 对象与接口

`schemas.py` 定义 v1 任务、预算、设计、分析规格、尝试、产物、人工请求、模型与
工具调用及动作的辨识联合。输出支持系数、标量、矩阵、效应路径和表格；缺失
推断字段用 null 加原因表示，禁止非有限数值。执行状态、提取状态与核验状态
各有契约。中文系统提示与交互语言字段固定为 zh-CN，协议标识保持标准拼写。

`ports.py` 的 ModelClient 返回动作或统一错误，附带逐次模型调用和用量；
AnalysisBackend 隔离能力、帮助、检查、执行和取消；RunStorePort 隔离状态与
证据选择。这里只定义边界，不创建空的生产后端或替代研究循环。

## 九表与事务

`migrations.py` 直接创建九表 SQLite v1：runs、designs、experiments、attempts、
artifacts、human_requests、events、model_calls、tool_calls。`PRAGMA user_version`
是数据库版本；对象 schema_version、应用版本及设计版本独立管理。外键启用并
检查，同 run 的关联采用组合外键，设计版本、尝试号、事件序号及调用重试号
具有唯一约束。不可变规格、产物和追加事件由 SQL 触发器保护，历史不可删除。

`state.py` 集中实现状态转换与条件更新。创建问题、等待状态和事件同事务提交；
应用答复、设计确认、当前设计切换及事件同事务提交。每个写入连接持有 POSIX
排他锁直到关闭或进程退出，SQLite 写操作串行；只读查询不持锁、不迁移、不
初始化模型或 Stata。当前支持 macOS/Linux。

调用和尝试先登记，再在事务外调用外部服务。HTTP 成功和动作解析成功分开
记录，缺失用量保留 null，实际重试占用预算。缓存与 reasoning 子项不再加入
供应商 total，摘要明确未知请求数。开始时间不可改写，耗时由调用者的单调
时钟提供，所有持久化时间使用 UTC。

## 归档与恢复

文件归档先写恢复意图，fsync 临时文件，再使用同目录硬链接原子发布并移除
临时名；目标存在时失败，因此不覆盖已有文件。随后用短事务登记 artifact 及
相关状态。结果和核验的索引与 attempt 引用在各自事务中提交，重新提取产生
新 result ID，清空旧选择和核验引用。文件与 SQLite 不是跨系统原子事务。

恢复核对意图版本、run/设计/调用/尝试来源、文件大小及 hash，仅补登记匹配的
索引，不凭文件推断统计执行成功。无意图文件、未完成归档、缺失或改动的证据
和输入保持待处理；不删除原件。未终结调用记为 UNKNOWN，遗留尝试记为
INTERRUPTED，并暂停 run，保留原服务实例、会话及 task ID。确认旧任务停止后
才允许重试，不能用新 stdio 服务查询旧实例的 task ID。

## 确认与结果选择

人工答复绑定 request ID 与不可变设计 hash。同答复重复应用无额外副作用，
不同答复不能改写既有决定。新版本撤销旧的待答设计确认；旧版本已经应用的
批准也不会切换到新设计。暂停保留待答请求，恢复优先回到 WAITING_HUMAN。

结果选择和后续报告读取共用规则：当前已确认设计、匹配的 experiment/attempt、
执行已结束且成功、未取消、提取成功、输入和代码 hash 对应、精确结果与设计
hash 的核验通过，以及无阻断方法问题。计算核验必须来自程序，模型肯定回答
不能替代确定性核验。方法可用性、具体命令验证和当前识别假设分别表示。

M0 真实探测确认 Stata 18 软取消不充分：取消任务后需回收专用会话并核对 worker
退出，再建新会话。暂停或失败时在途尝试保留取消标记，迟到输出不能提交为成功。

## 阶段 2 的执行边界

`schemas.py` 保存共用 IV 声明；`stata_contracts.py` 保留兼容导出，并保存主体程序、保护清单、统一错误及
AnalysisOutcome；`ports.py` 的执行接口明确接收程序，不要求核心流程理解 MCP。
`stata_mcp.py` 白名单继承子进程环境，核对固定版本、实际通用工具和返回封套，
记录 Stata 构建、库 hash 与 MCP 版本。生产执行器不读取 AJR 参考答案。

`inputs.py` 建立独立备份、不可变快照和每次执行的工作副本；备份禁止链接原件，
已有备份和快照只核验，不覆盖。可变工作区在 run 外，完成输出再归档，因此
正常恢复不会把临时文件误记为孤儿产物。对本机代码访问的限制仍以开发计划的
受信任执行约定为准，这些检查不提供完整沙箱。

`stata_backend.py` 以专用会话和完整操作锁隔离估计；参数与代码先归档，调用
登记后再发 MCP 请求，后台 task ID 与服务实例、会话保持绑定。返回值在主估计
结束后立即读取。停止会话还须确认其已记录 PID 退出；取消后阻止会触发固定
服务自动重建会话的请求。不能确认终止时保留 INTERRUPTED/UNKNOWN 并暂停。
业务查询的遗留进程也阻止恢复，须先明确核对退出，再调用专用停止确认入口。

`stata_results.py` 目前只规范化明确的 2SLS、small、常规协方差口径。Stata 导出
真实参数名和 double 精度推断表，提取器与 e(b)/e(V) 对照，按声明条件逐行核对
e(sample)。主体代码、提取脚本、原始返回及具名样本证据绑定确切结果与设计。
任意合法命令仍走共用执行路径；缺少提取规则时保存原始输出并保持未规范化，
不套用回归系数表。重新提取不增加调用或统计尝试，重新核验并保留旧产物。

统一错误区分 Stata 错误码、连接、超时、取消、输入完整性、提取及终止不明。
提取失败不抹去真实执行成功；失败尝试不从日志挑数字构造成功结果。固定开发
验收脚本单独读取独立参考，不承担生产研究循环，不模拟真实人工修改已完成。

## 阶段 3 的决策与调度

`model_client.py` 只封装基础兼容请求。SDK 重试关闭，每次实际请求有独立 ID，
共享操作的重试号递增。请求先登记并归档，再执行网络 I/O；成功返回先保存传输
终态及原始用量，再解析动作。JSON 或契约错误仍是 HTTP 成功、解析失败，不创建
已执行工具。字段错误给出具体中文位置；不保存可能回显秘密的异常正文。

`harness.py` 生成工具说明及对应动作 schema，构造包含当前证据的中文上下文，
按本机命令能力和已确认设计分发。生产循环依赖 ModelClient、AnalysisBackend 和
RunStore，不直接调用 MCP 或 SDK。IV 声明属于共用动作契约，通用命令仍走同一
后端。模型来源写入帮助/检查及分析工具，内部 MCP 查询仍只计一个业务调用。

输入当前结果和发起分析的模型请求都有结果 ID；补充 experiment 同时保存依据
结果，形成“确切结果 → 请求 → 动作 → 工具 → 新尝试及结果”的记录。当前结果
再次读取时核验状态和 hash；结束动作只能引用本轮有效结果及其关联证据文件。
未知或历史数值不能混入当前有效结果。

新增分析占用研究轮次，技术修复保持同一 experiment 和 operation，要求上一尝试
已停止、规格不变且为最近一次失败；只能改代码，不能借重试改变研究设计。
连续错误、修复次数、模型和工具调用数以及累计活动时间分别有界。检查点使用
已有 artifact 表，保存近期反馈、查询缓存和耗时，不增加数据库表或迁移。

提出设计或问题进入 WAITING_HUMAN，程序返回而不自动确认。循环结束或动作预算耗尽
先进入 PAUSED，随后按阶段 6 的写作与发布约束产生论文；部分交付不记为完成。
有未终结调用时拒绝自动推进；阶段 5 的 CLI 恢复按下述进程来源核对后继续。

## 阶段 4 的审阅边界

`review.py` 通过小接口 ReviewModelClient 调用两项基础请求：design_consistency
检查设计与结果对应，interpretation 解释结果并提出有证据依据的建议。共享当前
设计、确切选中结果、规格及程序核验；不读取参考答案或重新执行统计。

`ResultReviewer` 使用 semaphore 限制同一实例最多两项模型 I/O，批次锁串行不同
批次。网络等待在短事务之外，`asyncio.gather(return_exceptions=True)` 保留每项
成功或错误。统一模型适配器为每项执行独立超时，审阅强制零重试；外部取消先
取消在途请求并归档，已完成的另一项仍保留。异常正文不进入产物。

一次 review_results 对应一个父 tool call 和两个独立 model call。请求分别保存
parent_tool_call_id、context_design_id、context_result_ids、UTC 起止区间和原始
usage。结果 ID 列表必须与发送的输入完全匹配，发现及建议只能引用已提供结果。
两份规范化意见分别归档，并保存一个聚合批次；失败不伪造模型请求、输出或用量。

开始及结束时都重新检查当前确认设计、选用结果和证据 hash；输入失效或留下未知
调用状态时暂停。意见中的 pass/fail/pending 属于模型判断，不更新 ValidationRecord，
也不改变结果选择和人工答复。ResearchLoop 只有配置审阅器才开放该动作，把完整
批次反馈给下一轮模型；不启动额外 Agent runtime，不新增数据库表、迁移或依赖。

批次耗时取整个操作墙钟时间，不将并发请求耗时相加。离线测试用屏障检查两项
请求同时进入 HTTP 边界；真实验收另以实际模型调用的 UTC 区间重叠作证据。

## 阶段 5 的 CLI、人工解释和恢复

`cli` 只负责输入和装配，`session` 调用原研究循环、模型适配器与 Stata 后端。
`start` 在任务、后端和执行配置校验后创建 run；不新增测试替身 CLI 模式。
`status` 使用只读 RunStore，不读取模型配置，不导入或启动 MCP、Stata、psutil。
保存的 task 保留规范化输入与预算，`resume` 不接受后端覆盖。

`interaction` 先绑定 human request 与设计 hash，再保存脱敏原始输入。
控制命令直接应用；自然语言调用 PersistentModelClient.interpret_feedback，
只在绑定待答设计的 WAITING_HUMAN 状态允许这一种模型请求，统计调用仍被禁止。
解释失败或含糊保持原问题，明确修改调用 RunStore.revise_answer，在同一事务
保存原答复、不可变新版本和待确认请求；末尾失败整项回滚，不自动确认。
新版本关联原 request 及依据结果；重复或旧输入不会解锁另一个版本。

确认新版本时更换 current_design_id，当前结果按该设计过滤；旧记录不删除。
研究循环检查点关联设计，版本变化后清除旧近期反馈，保留数据及能力缓存。
人工解释活动耗时进入下一检查点，等待研究者思考的时间不算模型活动。
模型上下文包含已应用人工答复，程序选定意见与原始授权在验收记录中区分。

`session` 在明确待答点读终端，不使用无法取消的输入线程。SIGINT 首次请求
暂停，等待模型／执行器取消和资源回收后落盘退出。`/stop` 通过阶段 6 的只读导出保存现有材料，
缺少有效论文时为部分交付，排除完整模型请求／响应、秘密配置、备份和历史报告。

后端在创建专用会话前保存 intent，取得工作进程后保存 PID、出生时间、可执行
文件及业务关联。`recovery` 核对这些不可变归档，`processes` 仅处理匹配的进程。
PID 消失或复用则不给现有进程信号，二次出生检查消除获取进程对象期间的复用
风险。权限不足或身份不全时暂停，不通过新 MCP 服务查询旧 backend task ID。
旧工具停止后本地 UNKNOWN 关闭为 CANCELLED，原尝试仍为 INTERRUPTED，
服务端处理和未返回用量保持未知；成功尝试不重放。九表 SQLite v1 和锁格式不变。


## 阶段 6 的报告、证据与只读导出

`paper_contracts` 定义八章论文和逐项经验结论；`reporting` 使用存储层的当前选用
结果读取与核验，不复制一套更宽松的“最新成功结果”规则。程序为所有当前数字
提供事实编号、确切结果 ID/hash、规范化字段、Markdown 表行与 CSV 行，模型仅
撰写说明和占位符结论。资料中的变量名、标准方法名、实际样本条件及有来源的
年份允许作为元数据；其他阿拉伯数字与越界事实引用拒绝。中文数字和自然语言
的正确性不能仅靠结构校验证明，依然需要研究者抽查。

研究循环及客户端为写作预留一个实际调用，传输重试和两项审阅也不能占用它。
写作强制零重试，所有成功、失败和未知用量照常保存。写作从暂停或已完成会话
单独开启，不重跑分析；报告耗时另外归档，恢复检查点记录已计入的写作时间，
避免总预算重置或重复扣除。没有预算则确定性生成部分材料。

所有文件使用已有 `report` 产物类型及不可变新目录。文件归档后最后保存发布
清单；中断没有清单时不能成为新报告。发布及每次读取再次检查选择、设计、源
证据及表格数字，完整报告还核对写作调用与请求/响应 hash。`COMPLETED` 必须有
当前有效完整报告、有效选中结果且无待答或未终结调用；部分报告保留为 PAUSED。
旧版本清单或文件失效时不回退到更早成功论文。SQLite v1 九表、依赖与后端不变。

`exporting` 只读已有记录，白名单复制源输入、全部分析的代码/原始返回/规范化
结果/核验/日志/环境；当前论文单独复制，完整提示词/响应、秘密配置、保护清单、
备份和历史报告排除。调用文件仅含关联与元数据。拒绝参数的工具调用保留在
逐次调用记录，不伪造实际执行的 experiment 或 attempt。部分文件损坏明确列入
排除及交付限制，不让坏文件提供当前论文数字。导出前后比较会话元数据和当前
报告，再原子发布新目录，防止复制期间混合不同版本。

复现入口只适配受控标准包装器，使用原输入/主体/提取文件及已记录种子；原脚本
不改写，派生脚本另有 hash 与源引用。遇到未识别环境、缺少文件或硬编码绝对路径
标记需人工适配，不声称可移植。当前 IV 案例迁移目录后通过全新本机 Stata 验证。


## 阶段七的方法映射与兼容

`RegressionSpecification` 与 `SummarySpecification` 是可选的新增提取声明，
与既有 iv 互斥，未声明的命令继续走通用原始归档。旧程序和动作缺少这些字段
时使用 null 默认值；SQLite 仍为九表 v1，无数据迁移、依赖或后端新增。
`stata_methods.py` 集中处理具体方法的结构条件与返回映射，报告仍消费统一的
CoefficientResult/ScalarResult，不在 CLI、存储和报告重复添加方法分支。

线性规格明确 t 自由度与 OLS/HC1；Logit 要求零一结果、满秩、收敛和观测信息
矩阵，使用正态推断并明确无 t 自由度。DiD 检查四格存在及交互项；RDD 检查
阈值、中心化、锐分配、交互项与带宽和两侧观测。它们不是识别假设检验。
估计变量与结构变量须已在输入中准备好，当前规范化主体只接受声明的单个
估计命令；复杂预处理或其他命令仍归档原始输出，不伪装规范化成功。

描述统计在主 do-file 内保存 r_snapshot.json，之后才允许 MCP 轮询；原 MCP
返回单独保留。规范化时核对快照与具名 double CSV，二者连同执行主体、包装器、
输入、提取脚本、样本检查共同绑定产物 hash。导出复现运行原主体与提取脚本。
`method_validation.json` 包含已执行参考的精确环境、映射代码 hash 与范围；
不同环境或代码显示 unverified，未验证形态仍不误读。

连续错误的自动推进上限保持持久化。新的研究问题 accept 事件只有在最后检查点
之后、属于当前设计时才允许恢复该错误计数；立即保存检查点消费此答复。
普通 resume 不绕过限制，累计调用与时间预算、分析重试计数和已成功任务保持。
