日期：2026-10-10。范围为开发计划「阶段 1 对象与状态」，不表示 M1 整体完成。
阶段 2 的生产 Stata 执行器、阶段 3 的模型研究循环，以及后续 CLI 人工交互与

协议字段、动作、状态、命令与依赖标识保持标准拼写。历史共享提交不重写。

## 交付内容

- `schemas.py`：v1 任务、预算、设计、分析规格、尝试、人工请求、产物、调用、
  动作与统一模型错误。首版创建和读取均限定 Stata，固定中文交互。结果支持
  系数、标量、矩阵、效应路径及表格，缺失推断字段保留 null 和原因。
- `ports.py`：ModelClient、AnalysisBackend、RunStorePort 三个小接口，未增加
  第二个分析后端、通用工作流引擎或外部状态服务。
- `migrations.py`：恰有计划规定的九张表，SQLite v1、同 run 外键、范围及唯一
  约束、查询索引和不可变历史触发器；未来数据库格式拒绝读写，保留原文件。
- `state.py`：run 目录、脱敏配置和环境清单、输入与代码 hash、排他锁、短事务、
  人工确认和版本绑定、调用重试与未知用量、不可覆盖归档、中断恢复，以及
  当前设计下有效结果的集中选择和再次核验。

任务示例现按正式 v1 ResearchTask 编写。阶段 0 的准备性示例不是已发布的状态
格式，不编造旧数据库迁移。应用版本仍为 0.1.0，数据库和对象格式分别为 v1。

## 本地检查

从缓存离线安装完整锁定依赖，再在新虚拟环境执行统一入口：

```sh
UV_PROJECT_ENVIRONMENT=tmp/stage1-clean-env uv sync --locked --offline --extra stata --group dev
tmp/stage1-clean-env/bin/python scripts/check.py
```

结果：Ruff 格式与静态检查、严格 mypy、75 项单元与契约测试、安装后模块入口
全部通过。Python 3.11.15，未新增运行依赖，`uv.lock` 未变。

| 重点 | 实际测试覆盖 |
| --- | --- |
| 保存与恢复 | 同一任务保存、关闭、恢复后后端、设计、状态及环境清单一致 |
| 数据库关联 | 九表、外键启用、错误 run/来源关联、枚举范围与重复版本被拒绝 |
| 人工决定 | 等待与事件原子提交；注入异常整体回滚；同答复幂等、旧 hash 拒绝 |
| 设计变更 | 旧批准不解锁新设计；已决定设计不能再次审批；旧规格保留 |
| 真实进程锁 | 第二写入进程被拒绝，只读并存；进程异常退出后锁释放 |
| 不可变归档 | 拒绝覆盖、路径越界及符号链接；SQL 禁止改写规格、产物和事件 |
| 归档中断 | 文件发布后、入库前中断可补索引；入库后意图清理失败可幂等恢复 |
| 未知输出 | 无归档意图或错误身份的文件只标待处理，不推定统计成功 |
| 输入与证据 | 缺失或 hash 改变导致暂停；选中结果读取时重新检查证据 |
| 格式版本 | 对象和数据库未来版本拒绝；只读打开不初始化或迁移空数据库 |
| 遗留任务 | 未终结调用变 UNKNOWN、尝试变 INTERRUPTED；保留旧实例及 task ID |
| 取消与重试 | 未确认旧任务停止禁止重试；迟到成功输出被拒；新尝试不用旧 ID |
| 结果选择 | 执行、提取与核验分开；必须属于当前确认设计及相应分析和尝试 |
| 精确核验 | 绑定确切结果和设计 hash；重新提取不继承旧通过标记或旧选择 |
| 核验责任 | 模型肯定回答不能替代计算检查；阻断方法问题禁止选入结论 |
| 调用与预算 | 传输和解析状态分开；重试逐次记录；失败仍占预算；未知用量非零 |
| 中文交互 | 系统提示、动作解释、帮助与参数错误中文；拒绝非中文语言配置 |
| 配置隐私 | 秘密字段在创建目录前拒绝，doctor 不输出凭证或含秘密的端点 |

这些测试使用明确标注的合成数据和调用记录，验证存储契约，不冒充真实模型、
MCP 执行或完成的研究流程。耗时由调用者提供单调时钟测量值；存储不把 UTC
差值当作真实执行耗时。实际统计核验规则在阶段 2 接入。
