## 命令与人工事务

- `start --task` 从任务文件启动；没有任务文件或直接执行入口时询问研究输入。
  后端优先级为 CLI、任务、默认 Stata，不支持的值在创建会话前拒绝。
- `resume` 保留后端与原问题。`--answer` 必须绑定请求 ID 和设计 hash；
  `--feedback` 用于没有待答问题的暂停会话。正常结束后的普通恢复只读已保存
  进度，不自动重跑。没有终端或指定 `--no-input` 时，在明确待答点保存并退出。
- `/accept`、`/reject <理由>`、`/pause`、`/stop` 无需模型解释。
  自然语言和 `/revise <说明>` 逐次调用基础模型，保存原始输入、解释和用量；
  含糊意见保持待答，不能把修改误作批准。
- 修改答复、新设计版本及新确认请求在同一短事务内保存。完整新设计先展示
  差异再等待确认，旧批准不会解锁新版本；重复输入不重复请求或创建版本。
  变量表的键使用实际列名，样本规则使用 Stata 条件表达式。
- 确认新版本后当前结果读取按新设计过滤；旧设计、尝试、结果与报告仍留作
  历史。停止快照只复制当前有效结果和关联代码，包含历史摘要但不复制旧报告、
  模型原始请求／响应或备份。论文和可独立运行的复现包属于阶段 6。
- `status` 只读数据库汇总设计、进度、问题和调用次数、失败、重试、已知用量；
  不要求模型凭证、Stata、MCP 服务或原始数据仍存在，未知用量保留 `null`。

## 暂停及遗留进程

运行前登记专用 MCP 会话派发意图，取得工作进程后归档 PID、出生时间、可执行
文件与 run/tool/attempt/service/session 关联。Ctrl+C 先取消在途请求、回收专用
会话并落盘，退出码为 130；等待输入时暂停保留原问题，不留下输入线程。

硬中断后首先恢复文件和数据库，再核对原专用进程身份。PID 已消失或复用时
不给新进程发信号；身份匹配才回收。缺少身份、访问受限或退出不明时保持暂停。
不向新 MCP 服务发送旧实例的 task ID，不把本地取消改记为服务端成功；未返回
的模型用量和服务端处理状态保持未知。正常完成的尝试不因恢复而重放。

真实生命周期验收命令：

```sh
uv run --locked --extra stata --group dev python -m scripts.validate_stage5_interrupt
```

两项使用生产会话和执行器运行固定 CPU 循环，明确是开发夹具，不是模型研究决策：

| 场景 | 真实信号与后续行为 | 尝试状态 | 退出确认 | 模型请求 |
| --- | --- | --- | --- | ---: |
| Ctrl+C | SIGINT，保存并退出，退出码 130 | CANCELLED | 已确认 | 0 |
| 硬中断 | SIGKILL，实际 CLI resume 核对进程并执行 /stop | INTERRUPTED | 已确认 | 0 |

每项仅一个尝试，工作进程出生身份已保存，退出已独立核对。硬中断后没有新统计
尝试，停止快照成功生成。Stata 使用本机已有 18.0.185 副本，未下载更新包。
