# 阶段 4 验收记录

日期：2026-10-10。范围为开发计划「有界并发」。基于阶段 3 已保存并核验的两项
真实 Stata 结果，进行设计一致性和解释/后续分析两项审阅，接入主循环反馈。
完整 CLI、真实人工修改和论文输出属于阶段 5–6，当前不是 M1 整体完成。

## 实现及约定

- 两项审阅各发送一次基础兼容模型请求，不创建独立 Agent runtime。SDK 隐式
  重试为 0，审阅显式重试也为 0；主循环原有请求重试约定保持兼容。
- 同一审阅器实例并发上限为 2，不同批次串行。每项默认最多 60 秒，主循环
  剩余活动时间进一步限制请求。请求预算不足两项时不发送，不伪造模型调用。
- 每项模型调用绑定同一个 review_results 父工具调用、当前设计及确切输入结果。
  中文请求、原始响应、规范化意见分别独立归档；保留实际起止时间和原始 usage。
  并发请求耗时不相加冒充批次耗时，未知用量保持 null。
- 聚合使用 asyncio.gather(return_exceptions=True)。局部失败仍保留完成的意见，
  明确标记 partial；外部取消终结在途请求并保存独立输出，完成的另一项不丢失。
- 校验报告角色、设计和完整输入结果列表，发现及建议只允许引用请求内的结果。
  开始和结束时检查当前结果、确认设计及证据 hash，输入失效则暂停并拒绝有效批次。
- 完整批次进入主循环近期反馈。模型意见的 pass/fail/pending 不修改程序核验、
  结果选择或研究者决定；建议不自动变成新设计或已执行统计。

新增 ReviewModelClient、ReviewReport/ReviewResponse 和审阅聚合对象，复用已有
model_calls、tool_calls 和 artifacts。九表 SQLite v1、应用版本 0.1.0、依赖与
锁文件不变；没有迁移、运行框架或新统计后端。

## 联调失败保留

首轮真实验收已出现区间重叠，但解释审阅把 raw_artifact_ids 填入了报告的
result_artifact_ids。严格引用校验记为 HTTP 成功、解析失败，设计审阅的成功
意见独立保留，父调用为 FAILED，聚合批次为 partial。未把原始文件 ID 当作
合法结果，未覆盖失败记录，也没有自动重试该项。

将请求顶层的 design_id、result_artifact_ids 及逐字复制提示明确给模型后，重新
发起完整审阅批次通过。失败轮实际用了 2 次模型请求、1 次业务调用和 13,064
tokens；本阶段累计 5 次模型请求、2 次业务调用及 43,000 已知 tokens。连同
阶段 3，同一 run 累计 8 次模型请求、7 次业务调用和 72,707 tokens，保留
1 次解析失败和 1 次父工具失败，未提高原定调用预算。再次执行验收前检查剩余
预算，不能反复使用已耗尽的 run。

[脱敏证据](evidence/stage4_reviews.json) 保存成功源码 hash、逐次请求与输出 ID、
角色报告、后续决策、输入 hash 和首轮失败。实际请求/响应、数据库和原始日志
留在忽略的 runs/ 与 local_reference/stage4/。阶段 3 设计确认仍为开发夹具，
不算真实人工修改；阶段 3 历史证据保留其原始源码 hash 与当时计数。
